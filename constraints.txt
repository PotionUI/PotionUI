# PotionUI backend constraints — pinned transitive closure for the 0.0.1
# support matrix (Linux x86_64 + NVIDIA CUDA).
#
# Frozen from the maintainer's known-good venv on 2026-07-16
# (`PYTHONPATH=./venv/lib/python3.12/site-packages python3.12 -m pip freeze`,
# since ./venv/bin/python itself is a dangling symlink in some containers —
# the interpreter resolves fine once site-packages is put on PYTHONPATH).
#
# Install contract:
#   pip install -r requirements.txt -c constraints.txt
#   pip install -r requirements-dev.txt -c constraints.txt   # contributors only
#
# requirements.txt / requirements-dev.txt stay in readable >=/direct-dep form;
# this file pins every package (direct AND transitive) to the exact version
# known to work together, the same way `pip-compile`/`uv pip compile` output
# would, without requiring either tool to be installed to regenerate it —
# `pip freeze` against the known-good venv was sufficient here.
#
# CUDA reality: torch/torchvision/torchaudio/xformers/triton below are plain
# PyPI wheels (`pip show torch` has no local +cuXXX version suffix, and their
# dist-info carries no direct_url.json, i.e. they were NOT installed from a
# `--index-url`/`--extra-index-url` or a local wheel). Since torch's PyPI
# wheels now declare their CUDA libraries as ordinary dependencies
# (nvidia-cublas, nvidia-cudnn-cu13, nvidia-nccl-cu13, cuda-toolkit, triton,
# ...; see torch's own Requires-Dist), a plain `pip install -r requirements.txt
# -c constraints.txt` pulls a working CUDA 13.0 stack with NO extra pip flags.
# The nvidia-*/cuda-* pins below are that transitive closure, captured for
# reproducibility; do not hand-edit them independently of torch.
#
# Excluded from this file (do not add to constraints or requirements*.txt):
#   - sageattention: optional GPU attention accelerator, installed on-demand
#     at runtime by the admin "native optimizations" panel
#     (src/platform/runtime/native/optimizations/catalog.py) via
#     `pip install git+https://github.com/thu-ml/SageAttention --no-build-isolation`.
#     It's a git ref built against the already-installed torch/CUDA, not a
#     reproducible index install, and it's optional — absence must not block
#     `pip install -r requirements.txt -c constraints.txt`.
#
# Feasibility note: splitting this into install profiles (core
# web vs. native-ML vs. media) was evaluated and rejected for 0.0.1.
# `src/bootstrap/container.py` imports `GpuManager` from
# `src.platform.runtime.gpu`, which does `import torch` at module level —
# so the composition root (`build_container()`) transitively imports torch
# unconditionally, before any preset/pipe is ever selected. A profile split
# would need `GpuManager`'s torch usage pushed behind a lazy import first.
# Tracked as future work, not attempted here.
#
# Regenerate by re-freezing the known-good venv and re-running this file's
# generation command above, then re-diffing against requirements.txt /
# requirements-dev.txt (tests/scripts/test_constraints_cover_requirements.py
# fails loudly if a direct dependency falls out of coverage).
