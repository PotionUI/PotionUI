# CPU-only test-runner subset of requirements.txt, for backend-tests.yml.
#
# Derived by starting from requirements.txt and removing packages that (a)
# expect a CUDA toolkit to build/install cleanly, or (b) nothing in `tests/`
# or an import chain reachable from it ever imports. Verified by grepping
# `src/` and `tests/` for each excluded package's import statements before
# dropping it - every hit found was a LAZY import (inside a function/method,
# never at module top level), so the excluded packages cannot break test
# collection even though the runtime feature that needs them stays untested
# on this CI job:
#
#   - xformers: CUDA-specific attention kernels; never imported anywhere in
#     src/ or tests/ (diffusers/accelerate optionally use it if present, but
#     nothing in this repo requires it).
#   - mediapipe, ultralytics: ADetailer/detailer face+object detection;
#     imported lazily inside detailer_helper.py/detection.py methods only.
#   - snac: Maya TTS codec; imported lazily inside maya_model.py's
#     `_load_snac` method only.
#
# torch/torchvision are still listed with the same version floors as
# requirements.txt - the workflow installs them from
# https://download.pytorch.org/whl/cpu, which resolves these same version
# specifiers to CPU-only wheels (no CUDA deps get pulled in, unlike the
# regular PyPI wheels constraints.txt documents).
#
# Deliberately NOT run through constraints.txt: that file pins the exact
# transitive closure of the maintainer's CUDA 13 venv (nvidia-cu13-*,
# GPU-build triton, etc.), which does not exist for a CPU-only install and
# would make `pip install -c constraints.txt` unsatisfiable here. CI resolves
# requirements-ci.txt's version floors fresh instead.
#
# Regenerate the exclusion list by re-grepping src/ and tests/ for each
# package's import statements whenever requirements.txt changes.
